02 workflow

One local loop, from folder picker to resumed thread.

The app is built around the actual runtime flow in the codebase: create a workspace from a folder picker, start a session, attach text or images, forward authorization decisions, and restore history on reload.

01

Choose a workspace

The desktop shell opens a folder picker and stores the local path string.

02

Start a session

The Go backend launches Codex with that directory as the working directory.

03

Stream everything

Messages, deltas, status updates, and auth cards arrive over SSE.

04

Resume later

Session history and thread IDs are persisted in SQLite for reload and continue.

03 stack

Desktop shell

Tauri hosts the app on Windows, macOS, and Linux with a native window and local dialog access.

  • workspace picker
  • file attachment input
  • native packaging targets: dmg, msi, deb

Conversation UI

React renders the workspace list, session list, message feed, auth prompts, and image input.

  • streaming assistant output
  • markdown rendering
  • session restoration

Backend bridge

Go exposes JSON-RPC and SSE, bridges to the Codex CLI, and persists the conversation state.

  • session lifecycle control
  • permission forwarding
  • SQLite-backed history
04 build

Run it in place, or package it for distribution.

The backend reads the Codex binary from `NEXTX_CODEX_BIN`, defaults arguments to `app-server --stdio`, and falls back to the system temp directory for local database storage when needed.

environment
NEXTX_CODEX_BIN=/path/to/codex NEXTX_CODEX_ARGS="app-server --stdio" VITE_BACKEND_URL=http://127.0.0.1:34121
package
